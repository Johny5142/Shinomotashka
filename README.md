# Точка колеса

Демонстрационный сайт шиномонтажа с заявками и кабинетом владельца. Astro SSR, TypeScript, PostgreSQL и Drizzle ORM. У каждого заказчика отдельное приложение и база данных.

## Локальный запуск

Нужны Node.js 24, npm и Docker Desktop с работающим Linux-движком.

1. Скопируйте `.env.example` в `.env`.
2. Задайте уникальный `ADMIN_PASSWORD` длиной от 12 символов.
3. Выполните `npm ci`.
4. Выполните `docker compose up -d db`.
5. Выполните `node --env-file=.env --import tsx scripts/migrate.ts`.
6. Выполните `npm run dev`.

Сайт откроется на http://localhost:8080, кабинет — http://localhost:8080/admin. Команда разработки загружает `.env` через Node.js.

Полный контейнерный запуск — `docker compose up --build -d`. Данные PostgreSQL сохраняются в именованном томе `postgres_data`. Команда `docker compose down` сохраняет том. Удаление тома уничтожает данные.

Миграции выполняются при `npm start`, затем запускается собранный сервер. Инициализация создаёт услуги и настройки только для пустой базы. Изменение `ADMIN_USERNAME` или `ADMIN_PASSWORD` и перезапуск обновляют учётные данные владельца. При смене пароля старые сессии отзываются.

## Демонстрация

`DEMO_MODE=true` включает заметную пометку, тестовую заявку и ежедневный сброс услуг, настроек и обращений при первом запросе после истечения 24 часов. Данные общие для всех посетителей. Не вводите реальные персональные сведения. Пароль демоадминки сообщается получателю отдельно и не публикуется на сайте.

Маршрут `/api/health` проверяет доступность базы. Без базы сайт возвращает страницу временной недоступности, а API — JSON с HTTP 503.

## Telegram

Укажите `TELEGRAM_BOT_TOKEN`. Для клиентской установки укажите `TELEGRAM_CHAT_ID`, для демо — только `TELEGRAM_DEMO_CHAT_ID`. Демо никогда не использует клиентский chat ID.

Заявка сначала сохраняется, затем выполняется попытка отправки уведомления с таймаутом. При сбое заявка остаётся в кабинете, там доступен повтор. Автоматической фоновой очереди в этой версии нет. Одновременные отправки блокируются на уровне заявки. После неопределённого сетевого сбоя повтор уведомления может продублировать сообщение в Telegram, сама заявка в базе остаётся одна.

## Проверки

- `npm test` — пароль и валидация.
- `npm run build` — TypeScript и сборка Astro.
- `node --env-file=.env --import tsx scripts/verify.ts` — интеграционная проверка работающего локального демо. Изменённые цены восстанавливаются, тестовые заявки удаляются.
- `node --env-file=.env --import tsx scripts/verify-resilience.ts` — отказ Telegram и сброс демо в отдельной временной базе. Нужны права PostgreSQL на создание тестовой базы.
- `node --env-file=.env --import tsx scripts/verify-persistence.ts` — остановка и повторный запуск локальной базы через Docker, проверка HTTP 503 и сохранности обращений. Запускать только для локального демо.

## Timeweb Cloud

1. Создайте Git-репозиторий с исходниками и lock-файлом. `.env` не добавляйте.
2. Создайте PostgreSQL в Timeweb Cloud, сохраните строку подключения. Ограничьте сетевой доступ приложением. Для TLS используйте параметры подключения провайдера с проверкой сертификата.
3. Создайте приложение App Platform из репозитория, выберите Dockerfile. Сервер слушает `0.0.0.0:8080`, порт указан в `EXPOSE`.
4. Задайте переменные запуска `DATABASE_URL`, `ADMIN_USERNAME`, `ADMIN_PASSWORD`, `DEMO_MODE=true`, `COOKIE_SECURE=true`, `APP_ORIGIN=https://<технический-домен>`. `APP_ORIGIN` задаётся без завершающего слеша. При необходимости задайте Telegram-переменные.
5. Разверните приложение. Проверьте `/api/health`, отправьте тестовую заявку и войдите в `/admin`.
6. Настройте резервное копирование PostgreSQL и проверьте восстановление перед использованием реальных данных.

Публикация требует доступа к аккаунту Timeweb, Git-репозиторию и оплаченным ресурсам. Точный бюджет приложения и базы определяется в панели до создания ресурсов.

## Новый заказчик

Разверните тот же код с отдельной базой, отдельным паролем, `DEMO_MODE=false`, `COOKIE_SECURE=true`, своим `APP_ORIGIN` и своим Telegram-чатом. Заполните реальные услуги, контакты и график в кабинете. Начальные сведения вымышлены и требуют замены. Содержание согласия на обработку данных и сведения об операторе подготовьте для конкретного бизнеса до приёма реальных обращений.

Кабинет поддерживает редактирование семи начальных услуг. Добавление новых категорий, онлайн-бронирование временных слотов, загрузка фотографий и несколько сотрудников в текущий объём не входят.
